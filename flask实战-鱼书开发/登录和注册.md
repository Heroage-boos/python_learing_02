## 一、密码加密与属性描述符

### 1.1 密码为什么不能明文存储

数据库如果泄露，明文密码会直接暴露用户隐私。正确做法是存储密码的哈希值，验证时比较哈希而非明文。

### 1.2 werkzeug 哈希函数

```python
from werkzeug.security import generate_password_hash, check_password_hash

# 加密
hashed = generate_password_hash('mypassword')
# 结果类似：'pbkdf2:sha256:260000$xxx$yyy'

# 验证
check_password_hash(hashed, 'mypassword')   # True
check_password_hash(hashed, 'wrongpass')    # False
```

每次生成的哈希值不同（因为盐值随机），但 `check_password_hash` 可以正确验证。

### 1.3 利用 property setter 自动加密

这是两个项目共用的核心技巧——在 User 模型上通过 `@property` + `@setter` 实现密码自动哈希：

**fisher_end 实现**（`fisher/app/models/user.py`）：

```python
class User(UserMixin, Base):
    # 数据库列名是 password，但 Python 属性名是 _password
    _password = Column('password', String(128))

    @property
    def password(self):
        return self._password          # 读取：返回哈希值

    @password.setter
    def password(self, raw):
        self._password = generate_password_hash(raw)  # 赋值时自动加密

    def check_password(self, raw):
        return check_password_hash(self._password, raw)
```

**flask-cloudBook 实现**（`app/models/user.py:25-40`）：

```python
class User(UserMixin, Base):
    _password = Column('password', String(length=256), nullable=True)

    @property
    def password(self):
        return self._password

    @password.setter
    def password(self, raw):
        self._password = generate_password_hash(raw)

    def check_password(self, raw):
        result = check_password_hash(self._password, raw)
        return result
```

**使用效果**：

```python
user = User()
user.password = 'mypassword'   # 自动哈希，存入 _password
user.check_password('mypassword')  # True
```

**设计要点**：
- 列名 `'password'` 是给数据库看的（`Column('password', ...)`）
- 属性名 `_password` 是 Python 内部用的
- `property` 拦截 `user.password = xxx` 的赋值，自动调用 `generate_password_hash`
- 这比在视图函数中手动调用 `generate_password_hash` 更干净、不易遗漏

## 二、Jinja2 模式下的认证（fisher_end）

### 2.1 Flask-Login 体系

**初始化**（`fisher/app/__init__.py`）：

```python
from flask_login import LoginManager

login_manager = LoginManager()

def create_app():
    app = Flask(__name__)
    # ...
    login_manager.init_app(app)
    login_manager.login_view = 'web.login'
    login_manager.login_message = '请先登录或注册'
```

| 配置项 | 作用 |
|--------|------|
| `init_app(app)` | 将 LoginManager 绑定到 Flask 实例 |
| `login_view` | 未登录时重定向到的视图端点 |
| `login_message` | 重定向后通过 flash 闪现的消息 |

### 2.2 UserMixin

```python
from flask_login import UserMixin

class User(UserMixin, Base):
    # UserMixin 自动提供：
    #   is_authenticated  → True（只要不是 AnonymousUserMixin）
    #   is_active         → True
    #   is_anonymous      → False
    #   get_id()          → return str(self.id)
```

不继承 UserMixin 也行，但需要手动实现这四个方法。`get_id()` 决定了 session 中存储什么值来标识用户。

### 2.3 user_loader 用户加载器

```python
@login_manager.user_loader
def get_user(uid):
    return User.query.get(int(uid))
```

**流程**：请求到达 → Flask-Login 从 cookie 中读取 `user_id` → 调用 `user_loader` 函数 → 把返回的 User 对象绑定到 `current_user`

这是连接"cookie 中的 ID"和"数据库中的用户对象"的桥梁，**必须实现**。

### 2.4 login_user / logout_user

```python
from flask_login import login_user, logout_user

# 登录：写入 cookie
login_user(user, remember=True)
# remember=True → 生成永久 cookie（默认365天）
# remember=False → 生成会话 cookie（关闭浏览器后失效）

# 登出：清空 cookie
logout_user()
```

### 2.5 login_required 保护页面

```python
from flask_login import login_required

@web.route('/my/gifts')
@login_required
def my_gifts():
    return render_template('my_gifts.html')
```

**行为**：未登录用户访问受保护页面 → 自动 302 重定向到 `login_view` 指定的登录页。

**缺点**（前后端分离场景）：AJAX 请求收到 302 后无法自动跳转，浏览器也不会把页面切到登录页。

### 2.6 redirect 重定向与攻击防范

```python
# 登录成功后根据 next 参数跳转
next_url = request.args.get('next')
if next_url and is_safe_url(next_url):
    return redirect(next_url)
return redirect(url_for('web.index'))
```

**重定向攻击**：攻击者构造 URL `https://yoursite.com/login?next=https://evil.com`，用户登录后被重定向到钓鱼网站。

**防范方式**：
1. 使用 `url_for()` 而非直接拼接用户输入的 URL
2. 校验 `next` 参数是否为站内相对路径（`flask_login` 内部有 `is_safe_url` 检查）
3. 仅允许以 `/` 开头的相对路径

### 2.7 cookie 操作

```python
from flask import make_response

@web.route("/user/cookie")
def set_cookie():
    resp = make_response('Hello World')
    resp.set_cookie('name', 'zhangsan', max_age=100)  # max_age 单位：秒
    return resp
```

| 参数 | 说明 |
|------|------|
| `key` | cookie 名称 |
| `value` | cookie 值 |
| `max_age` | 过期时间（秒），不设为会话级别 |
| `path` | 生效路径，默认 `/` |
| `secure` | 仅 HTTPS 传输 |
| `httponly` | 禁止 JavaScript 读取（防 XSS） |

**应用场景**：广告追踪、记住登录状态、购物车（未登录时）、用户偏好设置（语言/主题）、首次访问判断。

## 三、前后端分离模式下的认证（flask-cloudBook）

### 3.1 核心问题：为什么不能直接用 @login_required

Jinja2 模式下，`@login_required` 对未登录请求返回 **302 重定向**，浏览器自动跟随跳转到登录页——这对页面导航是合理的。

但在前后端分离中，前端发的是 AJAX/fetch 请求，302 响应**不会触发页面跳转**。前端看到的是网络请求失败或拿到了登录页的 HTML——无法判断是否登录成功。

**解决方案**：自定义装饰器，返回 **JSON 格式的 401 响应**，由前端根据状态码自行处理跳转。

### 3.2 auth_required 自定义装饰器

**flask-cloudBook 实现**（`app/libs/auth.py`）：

```python
from functools import wraps
from flask import jsonify
from flask_login import current_user

def auth_required(fn):
    """前后端分离场景下的登录校验装饰器

    未登录时返回 JSON {code: -401, message: "请先登录"} + HTTP 401，
    而非 Flask-Login 默认的 302 重定向（AJAX 无法处理重定向）。
    """
    @wraps(fn)
    def wrapper(*args, **kwargs):
        if not current_user.is_authenticated:
            return jsonify({
                "code": -401,
                "message": "请先登录",
                "data": None,
            }), 401
        return fn(*args, **kwargs)
    return wrapper
```

**使用方式**：

```python
@web.route('/api/user/home')
@auth_required
def page_home():
    return success({"nickname": user.nickname, "email": user.email}, "已登录")

@web.route('/api/user/reset_pwd', methods=['POST'])
@auth_required
def reset_pwd():
    form = ResetPwdForm(data=request.json)
    # ...
```

**对比**：

| | `@login_required` | `@auth_required` |
|---|---|---|
| 未登录响应 | `302 → /login?next=...` | `200 + {"code": -401, "message": "请先登录"}`（HTTP 401） |
| 适用架构 | Jinja2 模板渲染 | 前后端分离 API |
| 页面跳转 | 服务端控制 | 前端根据状态码控制 |

### 3.3 前端请求封装

**flask-cloudBook 前端**（`frontend/src/lib/api.ts`）：

```typescript
// 关键：credentials: 'include' 确保 cookie 随请求发送
async function request<T>(url: string, options?: RequestInit): Promise<T> {
  const res = await fetch(url, { ...options, credentials: 'include' })

  // 未登录 → 前端跳转登录页
  if (res.status === 401) {
    window.location.href = '/user/login'
    throw new Error('未登录')
  }

  if (!res.ok) {
    throw new Error(`HTTP ${res.status}`)
  }
  return res.json()
}

// session 检查（不触发跳转）
async function checkSession(): Promise<boolean> {
  try {
    const res = await fetch(`${API_BASE_URL}/api/user/home`, { credentials: 'include' })
    return res.ok && res.status !== 401
  } catch {
    return false
  }
}
```

**关键点**：
- `credentials: 'include'`：让浏览器在跨域请求中携带 cookie（等同于 `withCredentials: true`）
- 401 统一拦截：一处处理，所有 API 调用自动受保护
- `checkSession()`：静默检查，用于页面初始加载时判断登录状态

### 3.4 前端 401 拦截器模式

```typescript
// 统一请求函数中的 401 处理
if (res.status === 401) {
  window.location.href = '/user/login'  // 强制跳转到登录页
  throw new Error('未登录')
}
```

这与 Jinja2 模式中服务端 302 重定向是对称的——只是执行者从后端变成了前端。

## 四、WTForms 表单校验

### 4.1 注册表单

**fisher_end** 传统 Form 模式（`request.form`）：

```python
class RegisterForm(Form):
    email = StringField(validators=[DataRequired(), Email()])
    nickname = StringField(validators=[DataRequired(), Length(min=2, max=10)])
    password = PasswordField(validators=[DataRequired(), Length(min=6, max=32)])

# 使用方式（Jinja2 模式）
form = RegisterForm(request.form)
if form.validate():
    user = User()
    user.set_attrs(form.data)
    db.session.add(user)
    db.session.commit()
```

**flask-cloudBook** JSON API 模式（`request.json`）：

```python
class RegisterForm(Form):
    email = StringField("email", validators=[DataRequired(), Length(min=8, max=64), Email()])
    nickname = StringField("nickname", validators=[DataRequired(), Length(min=2, max=10)])
    password = PasswordField("password", validators=[DataRequired(), Length(min=6, max=32)])

# 使用方式（前后端分离模式）
form = RegisterForm(data=request.json)  # 注意：data= 而非 formdata=
if request.method == 'POST' and form.validate():
    user = User()
    user.set_attrs(form.data)  # 批量赋值
    db.session.add(user)
    db.session.commit()
    return success({...}, "注册成功")
else:
    return fail("参数校验失败", form.errors)
```

**关键差异**：
- Jinja2 模式：`RegisterForm(request.form)` — 数据来自 HTML 表单提交
- JSON 模式：`RegisterForm(data=request.json)` — 数据来自 JSON body
- 错误返回：Jinja2 模式渲染错误页面模板，JSON 模式返回 `{errors: ...}`

### 4.2 登录表单

```python
class Login(Form):
    email = StringField("email", validators=[
        Length(8, 64), DataRequired(),
        Email("电子邮箱地址不符合规范!")
    ])
    password = PasswordField("password", validators=[
        DataRequired(message="密码不可以为空，请输入你的密码！"),
        Length(min=6, max=32)
    ])
```

### 4.3 自定义校验器

WTForms 支持通过方法名约定添加字段级校验逻辑：

```python
class ResetPwdForm(Form):
    email = StringField(...)
    old_password = PasswordField(...)
    new_password = PasswordField(...)
    confirm_password = PasswordField(validators=[
        EqualTo("new_password", message="两次输入的密码不一致")
    ])

    # 自定义校验器方法命名规则：validate_<字段名>
    def validate_email(self, field):
        user = User.query.filter_by(email=field.data).first()
        if not user:
            raise ValidationError("该邮箱未注册")

    def validate_old_password(self, field):
        email = self.email.data
        if email:
            user = User.query.filter_by(email=email).first()
            if user and not user.check_password(field.data):
                raise ValidationError("原密码错误")
```

**命名规则**：`validate_<field_name>(self, field)` 方法会在该字段的通用校验之后自动执行。`field.data` 可获取当前字段的值，`self.email.data` 可获取同表单其他字段的值。

## 六、登录完整流程

### 6.1 Jinja2 模式（fisher_end）

```python
@web.route('/login', methods=['GET', 'POST'])
def login():
    form = LoginForm(request.form)
    if request.method == 'POST' and form.validate():
        user = User.query.filter_by(email=form.email.data).first()
        if user and user.check_password(form.password.data):
            login_user(user, remember=True)
            next_url = request.args.get('next')
            if next_url and is_safe_url(next_url):
                return redirect(next_url)
            return redirect(url_for('web.index'))
        else:
            flash('用户名或密码错误')
    return render_template('login.html', form=form)
```

### 6.2 前后端分离模式（flask-cloudBook）

```python
@web.route('/api/user/login', methods=['POST'])
def login():
    login_form = Login(data=request.json)
    if login_form.validate():
        user = User.query.filter_by(email=login_form.email.data).first()
        if user and user.check_password(login_form.password.data):
            login_user(user, remember=True)  # 写入 cookie
            return success({
                "email": user.email,
                "nickname": user.nickname
            }, "登录成功")
        else:
            return fail("登录失败,用户名或密码错误！")
    else:
        return fail("登录失败,用户名或密码错误！")
```

**流程差异总结**：

| 步骤 | Jinja2 模式 | 前后端分离模式 |
|------|------------|--------------|
| 校验失败 | `flash(msg)` + 渲染登录页 | `return fail(msg, errors)` |
| 登录成功 | `login_user()` + `redirect()` | `login_user()` + `return success()` |
| 记住登录 | cookie 由 `set_cookie` 写入 | 同上 + 前端 `credentials: 'include'` 携带 |
| 登出 | `logout_user()` + `redirect()` | `logout_user()` + `return success()` |

## 七、密码重置流程（flask-cloudBook）

```python
@web.route('/api/user/reset_pwd', methods=['POST'])
@auth_required
def reset_pwd():
    form = ResetPwdForm(data=request.json)
    if not form.validate():
        return fail("参数校验失败", form.errors)

    user = User.query.filter_by(email=form.email.data).first()
    if not user:
        return fail("用户不存在")

    # 通过 setter 自动加密新密码
    user.password = form.new_password.data
    db.session.commit()

    return success({}, "密码修改成功")
```

**需要的校验**：
1. 用户已登录（`@auth_required`）
2. 邮箱已注册（`validate_email` 自定义校验器）
3. 原密码正确（`validate_old_password` 自定义校验器）
4. 新密码长度合规（`Length(min=6, max=32)`）
5. 两次新密码一致（`EqualTo("new_password")`）

## 八、动态赋值 set_attrs

两个项目共用的 Base 基类方法：

```python
class Base(db.Model):
    __abstract__ = True

    def set_attrs(self, attrs_dict):
        for k, v in attrs_dict.items():
            if hasattr(self, k) and k != 'id':
                setattr(self, k, v)
```

**用途**：将表单校验后的 `form.data` 字典批量赋值到模型实例。

```python
# form.data = {"email": "test@example.com", "nickname": "测试", "password": "123456"}
user = User()
user.set_attrs(form.data)
# 等价于：
#   user.email = "test@example.com"
#   user.nickname = "测试"
#   user.password = "123456"  ← 触发 property setter，自动哈希！
```

**防御**：`k != 'id'` 防止客户端通过注入 `id` 字段覆盖已有记录。

## 九、最佳实践总结

| 实践 | 说明 |
|------|------|
| 属性描述符加密密码 | `@password.setter` 自动调用 `generate_password_hash`，不会遗漏 |
| `set_attrs` 批量赋值 | 结合 `form.data` 使用，比逐字段赋值更安全（排除 id） |
| 自定义校验器 | `validate_<field>` 方法实现业务级校验（邮箱是否存在、原密码是否正确） |
| 前后端分离用 JSON 401 | 避免 AJAX 无法处理 302 重定向的问题 |
| `credentials: 'include'` | 跨域请求中携带 cookie 的唯一可靠方式 |
| 前端统一 401 拦截 | 在 `request()` 封装函数中一处处理，避免散落在各组件中 |
| `login_user(remember=True)` | remember 决定 cookie 是会话级别还是持久级别 |
| `next` 参数安全 | 仅允许站内相对路径，使用 `url_for` 而非直接拼接 URL |
