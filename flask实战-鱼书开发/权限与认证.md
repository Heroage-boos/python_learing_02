## 一、Flask-Login 基础

### 1.1 初始化链路

```python
# 第一步：模块级声明 LoginManager
from flask_login import LoginManager
login_manager = LoginManager()

# 第二步：在 create_app 中绑定
def create_app():
    app = Flask(__name__)
    login_manager.init_app(app)
    login_manager.login_view = 'web.login'        # 未登录时跳转的视图
    login_manager.login_message = '请先登录或注册'  # flash 消息
    # ...
    return app
```

**为什么不直接在模块里 init**：因为此时 Flask app 还没创建，必须用 `init_app()` 延迟绑定。这是 Application Factory 模式的标准做法。

### 1.2 UserMixin

```python
from flask_login import UserMixin

class User(UserMixin, Base):
    # UserMixin 自动提供的属性/方法：
    #   is_authenticated  → True (非 AnonymousUserMixin 实例)
    #   is_active         → True
    #   is_anonymous      → False
    #   get_id()          → return str(self.id)
```

`get_id()` 的返回值会被写入 session cookie。默认用 `str(self.id)`，如需自定义（如用 email 替代 id），可 override。

### 1.3 user_loader — 连接 cookie 与数据库

```python
@login_manager.user_loader
def get_user(uid: int):
    # Flask-Login 从 cookie 读取 user_id 后调用此函数
    # 用主键查询，最快
    return User.query.get(int(uid))
```

**执行时机**：每次请求到达时，Flask-Login 自动调用 `user_loader`。

**如果没有 user_loader**：`current_user` 始终是 `AnonymousUserMixin`，始终未登录。

**fisher_end vs cloudBook**：两个项目实现完全一致——都定义在 `app/models/user.py` 中。

```python
# fisher_end: fisher/app/models/user.py
@login_manager.user_loader
def get_user(uid):
    return User.query.get(int(uid))

# cloudBook: app/models/user.py:49-53
@login_manager.user_loader
def get_user(uid: int):
    user = User.query.get(ident=int(uid))
    return user
```

## 二、Jinja2 模式权限控制（fisher_end）

### 2.1 @login_required 装饰器

```python
from flask_login import login_required

@web.route('/my/gifts')
@login_required
def my_gifts():
    return render_template('my_gifts.html')

@web.route('/my/wishes')
@login_required
def my_wishes():
    return render_template('my_wishes.html')
```

### 2.2 内部工作原理

```
请求进入
  │
  ▼
@login_required 检查 current_user.is_authenticated
  │
  ├─ True  → 执行视图函数，返回模板
  │
  └─ False → 生成 302 响应
                Location: /login?next=/my/gifts
                携带 flash message: "请先登录或注册"
              │
              ▼
         浏览器跟随 302 → 显示登录页
              │
              ▼
         用户提交登录 → 成功后 redirect(next) → 回到 /my/gifts
```

### 2.3 next 参数与重定向攻击防范

```python
from flask import request, redirect, url_for
from werkzeug.urls import url_parse

@web.route('/login', methods=['GET', 'POST'])
def login():
    if request.method == 'POST' and form.validate():
        # 登录成功...
        login_user(user, remember=True)

        # 获取 next 参数
        next_page = request.args.get('next')

        # 安全检查：next 必须是相对路径（无 netloc）
        if not next_page or url_parse(next_page).netloc != '':
            next_page = url_for('web.index')

        return redirect(next_page)

    return render_template('login.html')
```

**攻击原理**：
```
https://yoursite.com/login?next=https://evil-phishing.com
```
用户登录后会被重定向到钓鱼网站。

**防范要点**：
1. `url_parse(next).netloc != ''` 检查是否有域名——有则拒绝
2. 只接受以 `/` 开头的相对路径
3. Flask-Login 内置了 `is_safe_url()` 辅助函数以达到同样目的

### 2.4 current_user 在模板中的使用

```html
<!-- Jinja2 模板中直接使用 current_user -->
{% if current_user.is_authenticated %}
    <span>欢迎, {{ current_user.nickname }}</span>
    <a href="{{ url_for('web.logout') }}">退出</a>
{% else %}
    <a href="{{ url_for('web.login') }}">登录</a>
{% endif %}
```

`current_user` 由 Flask-Login 通过 `LocalProxy` 自动注入模板上下文。

### 2.5 数据级权限控制

```python
# 确保只能删除自己的礼物
@web.route('/my/gift/delete/<int:gid>')
@login_required
def delete_gift(gid):
    with db.auto_commit():
        # 同时按 id 和 uid 过滤
        gift = Gift.query.filter_by(
            id=gid,
            uid=current_user.id
        ).first_or_404()
        gift.delete()
    return redirect(url_for('web.my_gifts'))
```

**关键**：`filter_by(uid=current_user.id)` 确保用户只能操作自己的数据，防止通过修改 URL 中的 `gid` 越权操作。

## 三、前后端分离模式权限控制（flask-cloudBook）

### 3.1 为什么不能用 @login_required

在前后端分离中，前端通过 `fetch` 发起请求：

```javascript
fetch('/api/user/home')
  .then(res => res.json())
  .then(data => { /* 渲染 */ })
```

如果后端返回 302 重定向，`fetch` 会**自动跟随重定向**，但：
1. 最终收到的可能是登录页的 HTML（而非 JSON）
2. 浏览器的地址栏**不会**变为登录页
3. 前端无法区分"正常响应"和"未登录被拦截"

### 3.2 auth_required 自定义装饰器

**源码**（`app/libs/auth.py`）：

```python
from functools import wraps
from flask import jsonify
from flask_login import current_user

def auth_required(fn):
    """前后端分离场景下的登录校验装饰器

    未登录时返回 JSON 401 而非 302 重定向。
    """
    @wraps(fn)
    def wrapper(*args, **kwargs):
        if not current_user.is_authenticated:
            return jsonify({
                "code": -401,
                "message": "请先登录",
                "data": None,
            }), 401
        return fn(*args, **kwargs)
    return wrapper
```

### 3.3 使用方式

```python
# 需要登录的 API 接口
@web.route('/api/user/home')
@auth_required
def page_home():
    return success({"nickname": user.nickname, "email": user.email})

@web.route('/api/user/reset_pwd', methods=['POST'])
@auth_required
def reset_pwd():
    form = ResetPwdForm(data=request.json)
    # ...
```

### 3.4 前端统一拦截器

```typescript
// frontend/src/lib/api.ts
async function request<T>(url: string, options?: RequestInit): Promise<T> {
  const res = await fetch(url, {
    ...options,
    credentials: 'include'  // 携带 cookie
  })

  if (res.status === 401) {
    // 统一处理：跳转登录页
    window.location.href = '/user/login'
    throw new Error('未登录')
  }

  if (!res.ok) throw new Error(`HTTP ${res.status}`)
  return res.json()
}
```

**优势**：所有 API 调用都经过这一个函数，401 处理集中化，不会遗漏。

### 3.5 session 静默检查

```typescript
async function checkSession(): Promise<boolean> {
  try {
    const res = await fetch(`${API_BASE_URL}/api/user/home`, {
      credentials: 'include'
    })
    return res.ok && res.status !== 401
  } catch {
    return false
  }
}
```

用于页面初始化时判断登录状态，**不触发跳转**（如果未登录只返回 false）。

## 四、两种装饰器的对比

| | `@login_required` | `@auth_required` |
|---|---|---|
| **所属项目** | fisher_end | flask-cloudBook |
| **未登录响应** | `302 → /login?next=...` | `200 + {"code": -401}` + HTTP 401 |
| **适用架构** | Jinja2 模板渲染 | 前后端分离 API |
| **浏览器行为** | 自动跟随 302 跳转 | 前端接收 JSON 后自行处理 |
| **闪存消息** | `flash('请先登录或注册')` | 无（前端自行展示提示） |
| **next 跳转** | 服务端控制 | 前端控制 |

## 五、访问权限分级

### 5.1 三个级别

| 级别 | 示例接口 | 权限要求 | 装饰器 |
|------|---------|---------|--------|
| 公开 | `/api/book/search` | 无 | 无装饰器 |
| 需登录 | `/api/user/home` | 已认证 | `@auth_required` |
| 需购买 | `/api/reader/xxx` | 已认证 + 已购买 | `@auth_required` + 业务判断 |

### 5.2 实现需购买权限

```python
@web.route('/api/reader/<int:book_id>')
@auth_required
def reader(book_id):
    # 第一步：检查是否登录（装饰器已处理）
    # 第二步：业务级权限——是否已购买
    order = Order.query.filter_by(
        user_id=current_user.id,
        book_id=book_id,
        status='paid'
    ).first()

    if not order:
        return fail("请先购买此书")

    # 已购买，返回阅读器所需数据
    return success({"book": book, "token": reader_token})
```

### 5.3 数据级别权限

```python
# 订单接口 — 用户只能查看自己的订单
@web.route('/api/orders')
@auth_required
def my_orders():
    orders = Order.query.filter_by(user_id=current_user.id).all()
    return success({"orders": [o.to_dict() for o in orders]})

# 而非：
# orders = Order.query.all()   ← 这会泄漏所有用户的订单
```

## 六、Cookie 与 Session 管理

### 6.1 login_user 做了什么

```python
login_user(user, remember=True)
```

内部实现（简化）：
1. 调用 `user.get_id()` → `str(user.id)`
2. 将 `user_id` 写入 Flask session（`session['user_id'] = user.id`）
3. 如果 `remember=True`：额外设置 `remember_token` cookie（长期有效）
4. 如果 `remember=False`：仅 session cookie（浏览器关闭后失效）

### 6.2 logout_user 做了什么

```python
logout_user()
```

1. 从 session 中移除 `user_id`
2. 清除 `remember_token` cookie
3. 使用 `session.modified = True` 标记需要重新生成 session

### 6.3 前后端分离的 Cookie 注意事项

```python
# 后端配置
app.config['SESSION_COOKIE_SAMESITE'] = 'Lax'     # 或 'None'（需配合 Secure）
app.config['SESSION_COOKIE_SECURE'] = False        # 开发环境 HTTP，生产环境应为 True
app.config['REMEMBER_COOKIE_HTTPONLY'] = True      # 禁止 JS 读取（防 XSS）
```

```typescript
// 前端配置
fetch(url, {
  credentials: 'include'  // 跨域发送 cookie
})
```

```python
# 后端 CORS 配置
from flask_cors import CORS
CORS(app, supports_credentials=True)
# supports_credentials=True 告诉浏览器允许携带 cookie
```

## 七、统一响应格式（flask-cloudBook）

```python
# app/libs/response.py
def success(data=None, message="操作成功"):
    return {
        "code": 200,
        "message": message,
        "data": data or {}
    }

def fail(message="操作失败", errors=None):
    return {
        "code": -1,
        "message": message,
        "data": errors or {}
    }

def auth_fail(message="请先登录"):
    return {
        "code": -401,
        "message": message,
        "data": None
    }, 401
```

前端统一解析：

```typescript
interface ApiResponse<T> {
  code: number
  message: string
  data: T
}

const res: ApiResponse<{email: string}> = await api.user.login(...)
if (res.code === 200) {
  // 成功处理
} else {
  // 失败处理，展示 res.message
}
```

## 八、最佳实践总结

| 实践 | 项目来源 | 说明 |
|------|---------|------|
| LoginManager 模块级声明 | 两个项目 | 配合 init_app 延迟绑定 |
| `filter_by(uid=current_user.id)` | fisher_end | 数据级权限控制，防止越权 |
| `auth_required` 替代 `login_required` | cloudBook | 前后端分离返回 JSON 401 |
| `credentials: 'include'` | cloudBook | 跨域 cookie 传递 |
| 前端统一 401 拦截 | cloudBook | 在 request() 封装中集中处理 |
| `@wraps(fn)` 保留原函数元信息 | cloudBook | 装饰器最佳实践 |
| `url_parse(next).netloc` 检查 | fisher_end | 防重定向攻击 |
| `is_safe_url()` | Flask-Login 内置 | 推荐直接使用 |
| 统一响应格式 | cloudBook | `{code, message, data}` 三元组 |
| 权限分级 | cloudBook 架构扩展 | 公开/登录/购买 三级 |
