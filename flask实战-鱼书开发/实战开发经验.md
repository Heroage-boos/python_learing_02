#### 文件夹/包 命名规范

| 类型 | 规范 | 项目示例 |
|------|------|---------|
| 包/目录名 | 全小写，下划线分隔 | `view_models/`, `http_helper.py` |
| 模块文件名 | 全小写，下划线分隔 | `yushu_book.py`, `book.py` |
| 类名 | 大驼峰（PascalCase） | `BookViewModel`, `BookCollection`, `SearchForm` |
| 函数/方法名 | 小写+下划线（snake_case） | `search_by_isbn()`, `package_single()` |
| 配置变量 | 全大写+下划线 | `DEBUG`, `SQLALCHEMY_DATABASE_URI`, `PRE_PAGE` |
| 蓝图名 | 小写字符串 | `Blueprint("web", __name__)` |

项目目录命名含义：
- `api/` — 对外接口模块（REST API）
- `cms/` — 内容管理模块（后台管理）
- `web/` — 前端页面路由模块
- `forms/` — 表单校验（WTForms）
- `models/` — 数据库模型（SQLAlchemy）
- `view_models/` — 视图模型（数据塑形）
- `spider/` — 爬虫/外部 API 调用
- `libs/` — 工具库（不依赖 Flask 的纯函数）

#### join在项目中使用
join使用示例
```py
fruits = ['apple', 'banana', 'cherry']
x = ', '.join(fruits)
print(x)
```
输出：
```
apple, banana, cherry
```

**项目中实际应用** — 将作者列表连接为字符串：
```python
# yushu_book API 返回 author 为列表：['鲁迅', '朱自清']
# ViewModel 中用 join 拼接成可读字符串
"author": "、".join(data["author"])  # 输出：'鲁迅、朱自清'
```
`join` 的优势：比 `for` 循环拼接更简洁，且不会在末尾多出分隔符。

#### 多线程使用场景

**Flask 开启多线程**：
```python
# 默认单线程，请求排队处理
app.run(host='0.0.0.0', debug=True, port=81)

# 开启多线程，可同时处理多个请求
app.run(host='0.0.0.0', debug=True, port=81, threaded=True)
```

**适用场景判断**：

| 类型 | 特点 | 多线程效果 | 示例 |
|------|------|-----------|------|
| IO 密集型 | 等待外部响应（网络/磁盘/数据库） | **有效** — 等待时释放 GIL，其他线程可执行 | 请求鱼书 API、查询数据库、读写文件 |
| CPU 密集型 | 大量计算 | **无效** — GIL 同一时刻只允许一个线程执行 Python 字节码 | 编译器优化、图像处理、加密计算 |

**鱼书项目场景**：搜索图书时请求外部 API 属于 IO 密集型，开启多线程有意义 — 线程 A 等待 API 响应时，GIL 释放给线程 B 处理其他请求。

**CPU 密集型的替代方案**：多进程（`multiprocessing`）、Celery 异步任务队列。

#### @classmethod和@staticmethod

**@classmethod** — 第一个参数为 `cls`，可访问类变量：
```python
# fisher4/5 中的用法：不实例化即可调用，URL 存为类变量
class YuShuBook:
    isbn_url = 'http://t.talelin.com/v2/book/isbn/{}'
    keyword_url = "http://t.talelin.com/v2/book/search?q={}&count={}&start={}"

    @classmethod
    def search_by_isbn(cls, isbn_no):
        url = cls.isbn_url.format(isbn_no)  # 通过 cls 访问类变量
        result = HTTP.get(url)
        return result

# 调用方式：直接用类名调用，无需实例化
YuShuBook.search_by_isbn('9787544291163')
```

**@staticmethod** — 无隐式参数，适合不依赖类/实例的工具方法：
```python
class HTTP:
    @staticmethod
    def get(url, return_json=True):
        r = requests.get(url)
        if r.status_code != 200:
            return {} if return_json else ''
        if return_json:
            try:
                return r.json()
            except requests.exceptions.JSONDecodeError:
                return {}
        return r.text

# 调用方式
HTTP.get('http://t.talelin.com/v2/book/isbn/9787544291163')
```

**选择依据**：
- 需要访问类变量（如 URL 模板）→ `@classmethod`
- 纯工具函数，不依赖类或实例状态 → `@staticmethod`
- 需要保存状态（如搜索结果）→ 实例方法（fisher6 重构方向）

## 处理None

**Python 中 None 的常见处理模式**：

```python
# 模式1：or 转空字符串 — 最常用
"pages": data["pages"] or ""        # None → ""，有值 → 原值
"summary": (data["summary"] or "")[:100]  # 先转空字符串，再截取

# 模式2：三元表达式
"title": data["title"] if data["title"] else "未知"

# 模式3：dict.get() 设默认值
book.get('price', 0)   # key 不存在时返回 0 而非 None
```

**为什么 `or ""` 有效？** Python 中 `None` 的布尔值为 `False`，所以 `None or ""` 返回 `""`。同理 `0 or ""` 也返回 `""`。注意：`0 or ""` 会把数字 0 也转为空字符串，如果 0 是有效值需用 `if x is not None` 判断。

**项目中示例**（ViewModel 中处理 API 返回的空字段）：
```python
book = {
    "title": data["title"],
    "publisher": data["publisher"],
    "pages": data["pages"] or "",           # 页数可能为 None
    "author": "、".join(data["author"]),
    "price": data["price"],
    "summary": (data["summary"] or "")[:100],  # 摘要可能为 None，且截取前100字
    "image": data["images"],
}
```

## 一个类中如果有大量的classmethod或者staticmethod

**问题**：如果一个类全是 `@classmethod`，没有任何实例属性，说明这个类只是被当作命名空间来用，而不是真正的"类"。

**fisher5 的 BookCollection** — 全是 classmethod，本质是把类当命名空间：
```python
class BookCollection:
    @classmethod
    def package_single(cls, data, keyword): ...
    @classmethod
    def package_collection(cls, data, keyword): ...
    @classmethod
    def __cut__book_data(cls, data): ...
```
调用方式：`BookCollection.package_single(data, q)` — 和模块级函数无本质区别。

**fisher6 的重构方向** — 改为实例方法，支持保存状态：
```python
class BookCollection:
    def __init__(self):
        self.keyword = ""
        self.total = 0
        self.books = []

    def fill(self, yushu_book, keyword):
        self.keyword = keyword
        self.total = 1
        self.books = [BookViewModel(book) for book in yushu_book.books]
```
调用方式：`books.fill(yushu_book, q)` — 通过实例保存搜索结果状态。

**选择依据**：
- **无状态工具类**（输入→输出，不需要保存中间状态）→ `@classmethod` 可接受
- **有状态业务类**（需要保存数据，多个方法操作同一份数据）→ 实例方法更合理

YuShuBook 也是同样演进：fisher5 用 classmethod（无状态），fisher6 用实例方法（搜索结果保存在实例上）。

## 直接返回对象的实例报错 TypeError: Object of type BookViewModel is not JSON serializable

**复现场景**：
```python
# 视图函数直接返回 ViewModel 实例
books = BookCollection()
books.fill(yushu_book, q)
return jsonify(books)  # ❌ TypeError!
```

**原因**：`jsonify()` 底层调用 `json.dumps()`，而 `json.dumps()` 默认只能序列化以下类型：
- `dict`, `list`, `str`, `int`, `float`, `bool`, `None`
- 自定义类的实例不在其中，因此报错

**解决方案** — 使用 `json.dumps` 的 `default` 参数：
```python
# fisher6 中的写法
return json.dumps(obj=books, default=lambda o: o.__dict__)
```
`default` 参数接收一个函数，当遇到无法序列化的对象时调用该函数。`o.__dict__` 将对象转为属性字典，字典可以被正常序列化。

**对比**：

| 方法 | 序列化自定义对象 | Content-Type |
|------|-----------------|-------------|
| `jsonify(books)` | ❌ 报错 | 自动设为 application/json |
| `json.dumps(books, default=lambda o: o.__dict__)` | ✅ 正常 | 需手动设 Response 的 Content-Type |

## 从json序列化看代码解释权反转

**核心思想**：`json.dumps` 的 `default` 参数，将"如何序列化"的解释权从 json 模块转移到了业务对象自身。

```python
# 默认：json 模块决定如何序列化 → 遇到不认识的类型就报错
json.dumps(books)  # TypeError

# default 参数：让对象自己决定如何序列化 → 解释权反转
json.dumps(books, default=lambda o: o.__dict__)  # 对象自己提供字典形式
```

**类比 ViewModel 的 fill() 方法**：
- 没有 ViewModel 时：视图函数直接返回原始 API 数据，展示逻辑散落在视图函数中
- 有 ViewModel 时：`books.fill(yushu_book, q)` — 数据如何展示由 ViewModel 自己决定

**设计意义**：
- **解耦**：数据处理（spider）和数据展示（ViewModel）分离
- **单一职责**：每个类只负责自己的序列化/展示逻辑
- **可扩展**：新增一种展示格式，只需新增 ViewModel，不影响原有代码

## 全局静态资源访问 和 蓝图静态资源访问

### 全局静态资源（Flask 应用级别）

```python
# app/__init__.py
app = Flask(__name__, static_folder='static', static_url_path='/statics')
```

| 参数 | 作用 | 默认值 | 本项目设置 |
|------|------|--------|-----------|
| `static_folder` | 磁盘上静态文件的目录（物理路径） | `'static'` | `'static'` |
| `static_url_path` | 浏览器访问静态文件的 URL 前缀 | 同 `static_folder` | `'/statics'` |

**优先级**：`static_url_path` > `static_folder`。即使文件夹叫 `static`，URL 也可以是 `/statics/...`。

**模板中引用**：
```html
<!-- url_for('static', ...) 会根据 static_url_path 生成 URL -->
<link rel="stylesheet" href="{{ url_for('static', filename='test_user_info.css') }}">
<!-- 渲染结果：<link rel="stylesheet" href="/statics/test_user_info.css"> -->
```

**常见坑**：
```html
<!-- ❌ 错误：href 缺少引号，浏览器无法正确解析 -->
<link rel="stylesheet" href={{ url_for('static',filename="test_user_info.css")}}">

<!-- ✅ 正确：href 值必须用引号包裹 -->
<link rel="stylesheet" href="{{ url_for('static', filename='test_user_info.css') }}">
```

### 蓝图静态资源（Blueprint 级别）

```python
# app/web/__init__.py
web = Blueprint("web", __name__, template_folder="templates")
```

Blueprint 可独立设置 `template_folder` 和 `static_folder`，路径相对于蓝图所在目录。

**模板查找顺序**：
1. 先查应用级 `app/templates/`
2. 再查蓝图级 `app/web/templates/`

本项目 `test_user_info.html` 放在 `app/templates/`（应用级），所以能被找到。如果蓝图有同名模板，蓝图级的优先。

### url_for 生成静态文件 URL 的原理

```python
url_for('static', filename='test_user_info.css')
# → 内部查找 app.static_url_path → '/statics'
# → 拼接结果：'/statics/test_user_info.css'
```

**图片引用同理**：
```html
<img src="{{ url_for('static', filename='测试图片-1.png') }}">
```
